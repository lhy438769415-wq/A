# 推送结构对比与 Demo（单策略 vs 全策略）

> 目的：让交易员（你）验收"推送里到底能看到什么信息"。
> 基准：今日 2026-07-31 实扫数据（日线 ALL，命中 17 = MTR反转 16 + AWIL趋势 1）。
> 范围：按你的要求，**本次只管"结构 + 0 命中告知"**，MTR 内部信息参差（部分缺价格/因子）暂不改动。

---

## 一、推送四段结构（单策略 / 全策略完全一致）

两段扫描走的是同一套 `_compose_report`，结构相同，差异只在"策略分组数量"：

| 段 | 内容 | 单策略 | 全策略 |
|---|---|---|---|
| ① 标题区 | 🔔 标题 / 时间 / 池子 | 同 | 同 |
| ② 统计区 | 🎯 命中总数 + **每个激活策略一行** | 1 行 | 最多 6 行（含 0 命中） |
| ③ 信号行 | 📌 每组标题 + 每只一行精简 | 1 组 | 多组（按优先级） |
| ④ 图表预告 | 📊 即将推送 / 实际出图 / 折叠汇总 | 同 | 同 |

**唯一结构性差异**：统计区行数 = 激活策略数。单策略恒 1 行；全策略现在会列出全部 6 个（含今天没符合的）。

---

## 二、Before / After（全策略"0 命中告知"）

**Before（今日你收到的，4 个 0 命中策略被吞）：**
```

   • AWIL趋势: 1 只
```
→ 交易员会以为"系统今天只跑了这 2 个策略"。

**After（本次已改，列出全部激活策略）：**

→ 交易员清楚知道"6 个策略都扫了，4 个今天没符合"。

## 四、验收要点（请确认）

1. **0 命中告知**：全策略扫描时，统计区是否应列出全部 6 个策略、0 命中的标 `(今日无符合)`？—— Demo B 即为目标形态。
2. **单策略结构**：Demo A 是否满足"一眼看到策略 + 全部标的 + 价格/因子"？
3. **信息字段**：每条信号的 `入场/止损/止盈/R:R` 与 `●因子证据` 是否是你做决策需要的？（MTR 部分标的缺价格/因子——本次按约定不改，待你后续决定。）
4. **图表洪流保护**：超过 10 张图时只推 10 张、其余折叠为文字——是否符合预期？
