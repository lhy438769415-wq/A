## 2. 建议 1：新高重置（New High Reset）

### 源码现状（已核实）
- 突破定义：`core/strategies/gap_h2_strategy.py:197-198`
  ```python
  _gap_floor_raw = df['high'].rolling(window=60).max().shift(2)
  df['is_breakout_h2'] = is_hh_hl & (df['low'] > _gap_floor_raw - 1e-3)
  ```
- 状态机：`gap_h2_strategy.py:229-248`。用 `groupby(_bars_since_breakout)` 把"突破后所有 K 线"绑成一个组，组内找 `LHLL → HH → LHLL`。
- `is_hh`（line 231）只是 `high > high.shift(1)`（比前一根高），**不是"突破后创新高"**。
- **确认：代码里没有任何"突破后创新高则重置计数器"的逻辑。** 用户描述的情形确实没被处理。

### 这是不是 bug？
- 从严格 Al Brooks H2 看，**是真实的结构性缺口**：H1 之后若价格创出高于突破尖点（Spike High）的新高，原波段起点已上移，旧结构作废；继续在旧结构上找 H2，确实可能买到"新一段趋势里的回调"甚至翻转起点。
- 但"最致命"言过其实——它只影响"突破后先弹 H1、再冲新高、再跌"这一小类路径。是否真亏、亏多少，必须数。

### ⚠️ 一个被忽略的重叠：高潮规避器已部分覆盖
- 组内最大高 `_group_max_high`（line 261）若 ≥ TP（`_target_uncond`），信号会被 `_mm_not_reached`（line 262）**直接作废**。
- 也就是说：H1 后的新高如果已经冲到了对称目标位，本就被高潮规避器杀掉了。
- **建议 1 的真实增量价值，只限于"新高但仍低于 TP"的那部分路径**——比阿布描述的"史诗级"窄得多。回测时必须单独剥离这部分来看。

### 实现要点（若要做）
- 在组内追踪 `spike_high`（突破根或组内绝对高点）；当 `high > spike_high` 时，把 phase1/phase2 计数清零，并把该新高设为新起点（重置背景）。
- 注意：由于 `_gap_floor` 锚定在突破根（line 205-209），且滚动 60 高随组内抬高，组内几乎不可能再触发"真突破"（low > 抬升后的 60 高），所以**不会自动开新组**——重置必须显式写。
- 影响范围：只改信号触发（一/二类），**不动 SL/TP**（floor 不变）。

### 必须做的验证
- 标记"被重置逻辑杀掉的原信号"，看这批信号历史上是净赚还是净亏。若它们本来就是亏的 → 重置真有价值；若它们也赚 → 重置反而砍掉了好信号。用同一数据集对比 EV / 胜率 / 信号数。

## 3. 建议 2：实体缺口（Body Gap）

### 源码现状（已核实）
- 当前是**真缺口**（True Gap）：`low > 60 周期最高高 - ε`（line 197-198）。
- floor = 60 周期最高高（line 205-209）；**SL = floor**（line 286）；**TP = 2×floor − PriorSwingLow**（line 259 / 292）。
- 用户原意：`Open > 60 周期最高收盘`。

### 阿布评估里的几个硬伤（必须指出）

**① 偷加条件（scope creep）**
阿布的"严格版"额外加了「突破 K 必须是强阳线（Close−Open > 0.5×Range）」「N+1 最低价不与 Res_Close 重叠」等，**这些不是用户提的**。若采纳，应明确分成两层：「用户的放宽」+「阿布自选的附加过滤器」，别混为一谈。

**② "A 股几乎不存在真缺口"是错的**
A 股天天有跳空高开/低开，真缺口很常见。阿布把 A 股和加密/外汇 7×24 市场搞混了。本系统数据是 A 股（Baostock），"拓宽到其他市场"的论据对本策略**不成立**。

**③ "信号几何级数增加且保持高胜率"是臆断**
放宽过滤器 = 信号数必然变多，这是定义性的；但胜率保持是**经验问题**，阿布当事实讲。必须回测。

**④ 没提风险几何变化（最关键）**
把 floor 从"60 最高高"降到"60 最高收盘"，意味着：
- **SL 更低 → 止损离入场更远 → 单笔风险变大、R 倍数变小**；
- **TP = 2×floor − PriorLow 也变低 → 目标变小**。
整笔**盈亏比（R/R）结构被改写**，不是"地基更牢"那么简单。
而且 floor 锚在突破根（line 205-209），**改了"什么是突破"会重锚整个组的 floor**——这是系统性改写，不是"多加点信号"。

**⑤ 连评级都受影响**
`compute_rating` 里的 `gap_size_pct`（line 113-115）由 `gap_top` 和 `sl` 算出，floor 一变，评分也变。

### 实现要点（若要做）
- 用参数 `GAP_DEFINITION = 'true' | 'body'`，把 line 197-198 的 `low > _gap_floor_raw` 换成 `open > _highest_close_raw`（**先只保留用户原意，不夹阿布的附加条件**）。
- floor 重新定义为"60 周期最高收盘"（锚定方式同 line 205-209）。
- 同步检查 SL / TP / 评级三条线。

### 必须做的验证
- 同一数据集跑 true vs body，对比：信号数、胜率、**EV（期望值）**、平均 R、最大回撤。重点看 R/R 是否恶化。若 body 版信号多了但 EV 不增甚至下降 → 不该合入。

## 4. 结论与下一步（评审建议）

1. 两条都是**合理的 PA 研究假设**，但阿布的评估把"假设"包装成了"已证实的史诗升级"，这是不专业的。
2. **不盲合入。** 两者都做成**参数化变体 + 同一数据集回测**，用 EV / 胜率 / 信号数三件套说话；数字过关再合入生产，不过关就留在 research。
3. **PA 铁律核查**：两条都仍是纯价格结构（OHLC 形态），没引入量能/指标/基本面，**不违反**系统红线，可以放心做实验。
4. 任何代码改动须过 `quality_gate`（裸 except / sys.path.insert 等红线），且**不碰 `data/*.db*`**。
