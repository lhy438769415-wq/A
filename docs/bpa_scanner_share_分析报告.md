# BPA Scanner（bpa_scanner_share）分析 + 与本项目的结合可行性评估

> 一句话结论：这是一个**独立的、可分享的「Al Brooks 价格行为（BPA）选股 + 看图精筛工作台」**。
> 它和咱们的 Brooks-AI 主项目（自动化多策略信号工厂）不是同一个东西，但**正好互补**：
> 主项目负责"自动找信号、AI 二审、推送到 Discord"；这个工具负责"把候选标的画出周/日/60分/5分四张图让你用眼睛亲手挑"。
> 目前它**能直接当独立看图工具用**，但"自动刷新数据"那一步在本机是坏的（缺一个文件），而且它和主项目用两套数据存储，要结合得先解决"数据打通"。

---

## 一、这个工具是干什么的

它是一套**"只做多（只能买涨、不能做空）"的 A 股波段（拿几天到几周）选股器**，核心思想完全来自 Al Brooks 的价格行为交易法（BPA）。

最关键的定位（写在它自己的契约文档里）：
- **它只做"排除明显不对的"和"把疑似对的挑出来给你看"，绝不替你下买卖决定。**
- 最终要不要买，由人（你）或者规划中的"第 3 步看图终审"负责。

这点和咱们主项目的"只推信号、不下单"一脉相承，但更保守——它连"排序选股"都不做，纯粹是**数据硬红线过滤 + 出图**。

---

## 二、它怎么工作（三步流水线）

### 第 1 步：数据初筛（step1_prescreen.py）—— 核心

把全市场日线数据，过 **11 道硬红线 + 1 道周线背景线**，给每只股票判一个"去向"：

| 去向 | 大白话 | 数量（本次跑的结果） |
|---|---|---|
| **REJECT**（拒绝） | 找不到任何可以做多的结构，直接扔掉 | 1202 只 |
| **WATCHLIST**（观察） | 有潜在买点，但"等回踩 / 等突破确认"后再说 | 284 只 |
| **STEP2_PUSH**（推送候选） | 需要看图确认的"底部反转"候选 | 6 只 |

> 注：本次扫描了 **1492 只**股票（候选名单写在 `candidates.json` 里）。

**11 道硬红线都是"数据能直接算的"，不需要看图**（这点设计得很聪明，机器能干的先干掉）：

- **维度 0 合规**：踢掉创业板(300)/科创板(688)/北交所/B股、ST/*ST/退市、非 T+1（今天买明天才能卖）、单价 ≥100 元。
- **维度 A 流动性**：当天成交额 < 1.5 亿的不要（流动性差，K 线会失真）。
- **维度 B 死股**：长期波幅 < 1% 且价格在一个极窄带里躺平（"铁丝网"，赚不到钱）。
- **维度 1 空头背景（AIS）**：收盘价 < EMA20 < EMA60 且 EMA20 还在往下 → 明显空头，严禁抄底。
- **维度 2 熊旗首弹**：深跌后第一次碰到 20 日线就反弹（80% 是空头旗形中继），除非是"放量大阳突破棒"才放行。
- **维度 3 下行通道（LH/LL）**：高点越来越低、低点也越来越低 → 下降结构，扔。
- **维度 4 区间上半区陷阱**：在震荡区上半部追涨（买在天花板），没突破动能就拒，有突破棒就先扔进观察池等回踩。
- **维度 5 撞阻力**：现价离上方强阻力太近、盈亏比 < 2:1 → 不今天买，等回踩；强多头趋势豁免硬杀但仍等回踩。
- **维度 6 信号棒质量**：只杀"高位长上影射击星"（当天买方被卖方在高位坚决拒绝）；**单纯收阴不算错**（回踩常态），不否决。
- **维度 C 抛物线尖峰**：涨太猛（收盘 > EMA20 的 1.3 倍且当天振幅翻倍）→ 不追尖，等回踩 EMA20。
- **维度 D 底部反转（MTR）**：长期下跌后接近前低(±5%)且跌速收敛 → 判为"潜在大级别反转"，进 PUSH 候选，**并覆盖前面 1/2/3 的拒绝**（因为反转正是反着这些下行结构来的）。

**周线背景线（维度 W）**：只在日线已经判为 PUSH/WATCH 时起作用，只降级、不升级。
- 周线三态：**WAIL**（周线多头背景）/ **WAIS**（周线空头背景）/ **WNEU**（中性）。
- 若 PUSH + 周线逆背景(WAIS) → 降级到观察（MTR 本就是逆势反转，高盈亏比，不硬杀）。
- 还会算一个粗 R 值（盈亏比 = 潜在盈利 / 潜在风险），R < 1.5 不推。

**它内置了大量"防呆自检"**（这点工程质量很高）：
- 数据不足 60 根 K 线、日期乱序/重复、数据陈旧、价格 NaN/Inf → 全部在前端拦下，不误杀。
- 摆动点计算严格防"未来函数"（只看截至今天的已知 K 线）。
- 所有除法/比值都有"分母有限且 >0"的保护。

输出：`step1_prescreen_results.json`（全量结构化）+ `step1_prescreen_report.txt`（人读报告）。

### 第 2 步：出图（step2_chart.py）

给"观察池 + 推送池"的候选，画 **2×2 四联 K 线图**：
- 左上：周线（背景大趋势）
- 右上：日线（信号主级别，画 EMA20/EMA60、近端阻力磁线；PUSH 候选额外画"前低 ±5% 反转区"和 R 值）
- 左下：60 分钟（执行细化）
- 右下：5 分钟（找低成本进场点，画"入场/止损/T1=1:1、T2=1:2"线）
- 涨红跌绿（A 股习惯），中文标签带字体自动回退（没中文字体也不乱码）。

最后生成一个 HTML 画廊（`charts/step2/step2_gallery.html`），可按"观察/推送"筛选、点开看大图。

### 第 3、4 步：规划中（还没做）

- step3 识图精筛（人工或视觉模型终审）、step4 推送/条件单 —— **目前只是界面上的占位页，没实现**。

### 两个界面（任选）

- **桌面端**（`desktop_app.py`，用 CustomTkinter）：不依赖浏览器，有 Dashboard / 初筛 / 图表 / 设置等页，能一键重跑。
- **网页端**（`app.py`，用 Streamlit）：浏览器打开，画廊体验更好。
- 两者都通过 `data_provider.py` 这个"契约层"读数据，不改写底层脚本。它还设计了**断网/境外也能看旧数据不白屏**的"快照模式"。

## 四、和咱们主项目（Brooks-AI）的对照

| 维度 | 主项目 Brooks-AI（debugV7.1_for_workbuddy） | 这个 BPA Scanner（share） |
|---|---|---|
| 定位 | **自动化多策略信号工厂** | **人工看图精筛工作台** |
| 入口 | `hunter.py` → 跑扫描 → 多策略命中最新 K 线 | `step1_prescreen.py` → 路由 → `step2_chart.py` 出图 |
| 策略 | 6 个策略注册在 StrategyRegistry（MTR_MASTER / 3K / 结构化缺口 / 缺口Pinbar / 缺口H2 / AWIL） | **没有"形态策略"**，只有 11 维"背景/合规"硬过滤 |
| AI 二审 | 有（DeepSeek 二次审计） | 无 |
| 推送 | 推 Discord + K 线图 | 不出推送，只出本地画廊 |
| 数据存储 | SQLite（WAL 模式，Baostock 离线 T+1，本地库） | **CSV 缓存**（baostock 日/周 + 新浪分钟） |
| 数据范围 | 日线 2023~今、周线 2011~今，约 3310 股 | 候选 1492 股（更窄，偏主板） |
| UI | 命令行 + Discord | 桌面端 + 网页端（更友好） |
| 哲学 | 重信号、自动推 | 重背景、只过滤、人终裁 |

**结论：两者不是"谁替代谁"，而是"自动找 + 人工挑"的上下游关系。** 而且有意思的是——它的 11 维初筛逻辑，比主项目里"隐式"做的背景过滤要更系统、文档更全（那份 contract.md 写得非常严谨）。

## 五、结合可行性评估（先说能结合的点，再说拦路虎）

### ✅ 互补价值（值得结合）

1. **主项目当"信号源"，它当"看图验证器"**：Brooks-AI 推到 Discord 的信号，你丢进 BPA Scanner 的四联图里用眼睛确认形态对不对——正好补上"AI 说买、但图看着不对"的盲区。
2. **它的 11 维初筛能当主项目的"前置过滤网"**：主项目跑 6 个策略前，先用它的硬红线把"空头背景/下行通道/流动性差/死股"干掉（本次 1492 只里这类有 478+208+161+125+... 一大堆），能**少跑策略、少推噪音信号、少刷屏**。
3. **它的四联图比主项目现有的单图更丰富**（多了周线背景 + 60分 + 5分进场 + 止损/T1/T2 线），可以直接升级主项目的出图。
4. **它的"人工剔除清单"机制干净**：`manual_exclude.json` 是个很顺手的手工"黑名单"，主项目其实也想要这种能力。

### ⚠️ 拦路虎（必须解决，否则结合是空谈）

1. **数据刷新那一步是坏的**：`fetch_universe.py` 引用了一个 `fetch_baostock.py`，但这个文件**不在目录里** → 日线数据没法自动更新。要么补这个文件，要么直接让它的 `data_provider` 去读主项目的 SQLite 库（这才是正路）。
2. **两套数据存储会打架**：它用 CSV 缓存，主项目用 SQLite。两套都去抓 Baostock，既重复又容易"一个更新了一个没更新"导致结论不一致。**最干净的做法：让它直接吃主项目的 SQLite（或主项目导出的 CSV），别自己再抓一份。**
3. **T+1/T+0 自相矛盾**：它的契约写"只做 T+1，T+0 ETF 一律拒绝"，但 `pool.json` 和 `candidates.json` 里还塞了 36 只跨境 T+0 ETF（如中概互联网 ETF）——这些会被维度 0 直接拒掉，是**半成品的痕迹**，结合前要清理。
4. **`screen_results.json` 是孤儿**：那是**老一版分类器**的产物（字段叫 cls/bp/hunter，和现在的 step1 完全两码事），现在没人读它。结合时**不要把它并进主项目**，它就是个历史遗留。
5. **第 3、4 步没做**：它目前只是"过滤 + 出图"两步，没有"终审"和"推送"。而"推送"主项目已经用 Discord 做了。所以结合时不用复刻推送，直接复用主项目的。
6. **运行环境不一致**：桌面端要系统 Python 3.11 + tkinter + customtkinter；网页端要 streamlit；主项目跑在托管 venv 里。它还在脚本里"硬编码清掉代理走直连"——而主项目可能依赖代理。环境要统一协调。
7. **它是"分享版"**：名字带 `_share`，设计目标就是"打包给别人用、不带绝对路径"。如果深度并回主项目，会牺牲这种可分享性。所以**先想清楚你是想"自己用"还是"发给别人用"**。

## 六、用户视角推演（假如结合了，你一天怎么过）

**场景：你（交易员 Leo）收盘后的真实工作流**

1. 收盘后，Brooks-AI 自动扫完 3310 只，6 策略 + AI 二审，**只推"今天末根触发"的寥寥几个信号到 Discord**。
2. 你对其中一两个感兴趣，但不想盲信 AI。你打开 BPA Scanner 的画廊，**看到这只票的周/日/60分/5分四张图**：周线背景是 WAIL 还是 WAIS？日线信号棒是不是真的"好进场形态"？5 分钟图上的"入场/止损/T1/T2"线画出来，盈亏比是不是 ≥2？
3. 你用眼睛一票否决或确认——这就是"人机协作"的闭环。
4. 反过来，你也可以**先把 BPA Scanner 的 11 维初筛挂到主项目前面**：每天开盘前自动把"空头背景/死股/流动性差"的票先剔掉，主项目就只在这些"背景干净"的票上跑 6 策略 → 信号更干净、Discord 不刷屏。
5. 遇到"AI 死活说好、但你觉得是飞刀"的票，你丢进 `manual_exclude.json` 拉黑，以后自动跳过。

**解决了你现在的三个痛点**：
- "AI 说买，图却不对" → 有图可肉眼复核。
- "信号太多太杂" → 11 维前置过滤先砍一刀。
- "我想自己圈定股票池" → pool.json + manual_exclude.json 给你完全的控制权。

## 七、建议的落地路径（按风险从低到高）

- **阶段 A（低风险，立即可做）**：把它当**独立看图 companion**。修好数据（让它的 data_provider 读主项目 SQLite，或补 `fetch_baostock.py`），专门用来"肉眼复核 Discord 信号 + 出四联图"。**不碰主项目代码。**
- **阶段 B（中风险）**：把它的 11 维初筛**抽成一个纯函数**，挂到 `hunter.py` 跑策略之前当"前置门"——减少假信号。这是最大收益点。
- **阶段 C（高风险，可选）**：写个小桥接，把主项目推的 PUSH 候选**自动喂进它的画廊**，一键出图复核。

**两件事先别做**：别把 `screen_results.json` 并进主项目；别让它和主项目各抓一份 Baostock（数据会漂移）。

## 八、需要你拍板的两件事

1. **你的目的是哪种？** (a) 只是想搞懂它是啥；(b) 想把它当独立看图工具用；(c) 想深度并回 Brooks-AI。这决定我下一步是帮你修数据、还是写桥接代码。
2. **数据怎么通？** 我建议让 BPA Scanner 直接读主项目的 SQLite（最干净），而不是让它自己再抓一份。要我按这个方向做吗？
