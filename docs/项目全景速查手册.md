## 〇、一句话：这项目是干什么的

一个**只推信号、不下单**的 A 股扫描系统。理论根基是 Al Brooks 价格行为（PA）。
每天收盘后扫一遍全市场 3312 只票，把符合形态的挑出来，落库、画图、推 Discord，**最终由你人来拍板买不买**。

桌面入口：`桌面\Brooks-AI操盘台.vbs` → `launch_dashboard.py` → `gui_dashboard.py`
命令行入口：`python hunter.py`（交互菜单 + CLI 参数）

## 三、数据怎么流（两条流水线）

**日线（每天跑）**
```
「下载行情」→ data_provider.update_daily_data_batch   （拉 Baostock 数据入库）
「策略扫描」→ hunter.run_pipeline_once → _scan_market （一次取数→算指标→6策略命中末根K线）
            → 评级 → 画图 → 推 Discord → 归档 signal_archive
```

**周线（每周跑一次，命令行里早就能跑）**
```
data_provider.update_weekly_data_batch  （多数情况拿本地日线在内存里合成周线，不走网络）
scan_engine.run_weekly_scan             （按家族路由：gap 家族归档 / 3K 不归档）
            → 推 Discord + 写 data/weekly_*_watchlist.json + 归档入库
```

**界面读什么**：GUI 全部从 `signal_archive` 表读（按 信号日期 + 策略）。

## 四、红线清单（违反即不可接受）

### A. 数据与库（最高优先级）

| # | 红线 |
|:---|:---|
| A1 | **不得碰 `data/*.db*`**（复制/备份/移动/删除），除非你**当时那条消息**明确许可；也不得触发平台的"改前自动备份" |
| A2 | 碰 `data/` 之前先说清：要干嘛、为什么、会不会产生临时文件；写类动作等你点头 |
| A3 | 碰完 `data/` 要给大白话小结（做了什么 / 真身库动没动 / 有无临时文件 / 有没有进回收站） |
| A4 | **不在无人看管时**跑数据重活（会话自动恢复后不自作主张、不后台定时跑） |
| A5 | **库结构冻结**：DDL 只能写在 `core/database.py`（主库）和 `tools/journal.py`（AI 日志库），别处出现 `CREATE/ALTER TABLE` 会被门禁直接拦下 |
| A6 | 禁止绕过代码直接用数据库工具手改线上库结构 |

### B. 代码质量（提交前门禁自动查）

| # | 红线 |
|:---|:---|
| B1 | 禁止 `sys.path.insert`（路径统一走 `core/paths.py`） |
| B2 | 禁止 `logging.basicConfig`（日志统一走 `core/log_config.py` 的 `get_logger`） |
| B3 | 禁止裸 `except:` 和 `from x import *` |
| B4 | 禁止 `get_logger()` 调用早于它的 import |
| B5 | **不得删测试来让检查变绿**（测试数守卫，当前基线 199） |
| B6 | 新文件 ≤ 500 行、新函数 ≤ 80 行，超了先拆 |
| B7 | 禁止 for 循环逐行遍历 DataFrame，必须 pandas/numpy 向量化（稀疏结构点除外，需注释说明） |

### C. 策略与评级（交易层面的第一性）

| # | 红线 |
|:---|:---|
| C1 | **PA 铁律**：因子只能是价格行为本身（开高低收 / 形态结构）。成交量、技术指标、基本面一律不得进因子 |
| C2 | 评级因子必须能在 `config/sop_rules.md` 的 16-Step SOP 里溯源（标注 Step 号），无法溯源禁入 |
| C3 | **缺口存活判定不能只看收盘价**，必须同时确认最低价没击穿缺口下沿 |
| C4 | 缺口生命周期过滤**必须包含信号当根 K 线**本身，不能从下一根才开始查 |
| C5 | 日线策略引用周线数据时，只能用**上周已走完**的周线，禁用本周未完成的 |
| C6 | 字母评级（A+/A/B/C/D）已证伪，**不得恢复**；只显示命中因子证据 |
| C7 | 不实现市场状态（牛熊/震荡）自动识别，这个判断交给人 |
| C8 | 禁止新增独立的状态追踪，一律走 SignalTracker |

### D. 界面（GUI）特有

| # | 红线 |
|:---|:---|
| D1 | 后台长操作必须走 `progress_callback` + `root.after` 节流更新进度条，**禁止拿日志当进度**（双击 VBS 是 pythonw，没有终端窗口） |
| D2 | 改完 `gui_dashboard.py` 必须用**系统 Python 3.14** 跑"构造界面"最小脚本冒烟——门禁和 ruff 都查不出 Tk 版本能力缺口 |
| D3 | 单格着色用图片或独立控件，禁止用 Tk 9.0 才有的 Treeview 列 `style`（本机是 Tk 8.6，用了必崩） |
| D4 | 附加面板用 `place` 浮层放进视觉留白，**禁止新开 grid 列去抢 K 线图宽度** |
| D5 | K 线图一律复用 `notifier.generate_chart_bytes`，禁止另写绘图代码；横轴用整数 0..N-1 |
| D6 | 一个按钮只做一件事；红色「终止」按钮用于误触取消 |

### E. 交付与沟通

| # | 红线 |
|:---|:---|
| E1 | **沟通红线（最高优先级）**：任何术语首次出现必须紧跟一句大白话注释，禁止裸甩缩写。宁可啰嗦不可含糊 |
| E2 | **核实铁律**：任何"现状是 X"的断言，必须先读源码（带行号）或实测；没核实就明说"存疑"，禁止凭印象编数字 |
| E3 | **终端噪声**：交付前真跑入口肉眼确认没有告警刷屏；必须从源头规避，禁止用 `grep -v` / 重定向掩盖 |
| E4 | **不发散**：改动严格收敛在你明确要求的范围 + 确证的真 bug，不自开新活 |
| E5 | 面向你的产物交付前过一轮体验评审（信息不冗余、可读、可复制、字体安全） |

### F. 版本管理

| # | 红线 |
|:---|:---|
| F1 | 每个实质性改动后**即本地 commit**（不强制推送）。历史教训：仓库一度无 commit，导致 `data_provider.py` 被截断后不可恢复 |
| F2 | git 一律用系统 git `D:/Program Files/Git/cmd/git.exe`（沙盒内置 git 会误删 `.git` 对象致仓库损坏，已发生多次） |
