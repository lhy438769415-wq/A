# 防「源码被清空/截断」事故 — 系统约束建议

> 背景：2026-07-31 晚间 `core/data_provider.py` 被截断（0 内容），恢复后字节精确还原至
> 7/26 清空前状态 + P1-7 修复。根因调查指向「外部进程截断单文件」（编辑器/同步盘），
> 非 WorkBuddy 的清理弹窗（弹窗仅删了我的恢复脚手架临时文件，见
> `docs/investigation_cleanup_popup_2026-07-31.md`）。
>
> 但用户要求「宁可错怪也不漏掉」——即把「清理弹窗允许」当作潜在假设，建立防御纵深。
> 以下约束无论根因是外部截断还是误清理都有效。

---

## 一、事故复盘（已证实）

| 项 | 结论 |
|:---|:---|
| 爆炸半径 | 仅 `core/data_provider.py` 1 个文件（`core/` 其余文件 mtime 均为旧值） |
| git 可恢复性 | 仓库「No commits yet」；索引 blob `b89a3453` 已丢失；pack 仅含 7/25 基底 |
| 唯一恢复源 | 清空前留下的 `data_provider.cpython-314.pyc`（3.14 字节码快照）|
| 恢复结果 | 字节精确还原（8/8 函数逐字节一致），门禁/集成/相关测试全绿 |
| 根因 | 外部进程截断（无日志/无 swap 文件，无法 100% 确定）|

**核心教训**：仓库没有任何 commit，导致真实内容从未进入 git 对象库 → 一旦工作文件被截断，
git 直恢这条路完全断了。这是本次「不可恢复」的真正根因，与「是谁截断的」无关。

## 二、系统约束建议（按收益排序）

### 约束 1【最高收益】commit 例程化（根因修复）
- **为什么**：只要内容进了 git 对象库，即便工作文件被截断，也能 `git show HEAD:path`
  或 `git log` 秒级找回；且 git 默认不 gc 近期对象，不会像本次一样「blob 丢失」。
- **怎么做**：每个实质性改动后提交本地 commit（`git add -A && git commit`，不强制 push）。
  本仓库 `hooks/pre-commit` 已接 quality_gate，提交即顺带跑门禁。
- **现状**：仓库已暂存 224 个文件、尚未首提。本次已补做首次本地 commit 作为例程起点。

### 约束 2【已落地】源码收缩守卫（pre-commit 拦截）
- 新增 `hooks/guard_source_shrink.py`，在每次 commit 前检查：任何已暂存 `.py` 若为空，
  或相对 HEAD 行数跌到 < 50%，**阻断提交**。
- 效果：即使某次误清理/截断了文件，只要它还没被 commit，守卫就会拦下，要求人工复核。
  首次提交（无 HEAD）自动跳过。
- 这是针对「清理弹窗误删」假设最直接的兜底——截断文件无法静默入库。

### 约束 3【用户侧】把项目排除出同步盘
- 若根因是 OneDrive / 百度网盘等同步工具截断，最有效的是把
  `debugV7.1_for_workbuddy`（至少 `core/`、`data/`）加入同步盘**排除列表**，
  或把活动工作目录移出同步路径。
- 同步盘对频繁重写的大文件（SQLite `.db`、`.pyc`）极易产生写入冲突/截断。

### 约束 4【已存在】原始备份目录保护
- `debugV7.1_for_antigravity` 仍完好（Jul5 版），作为只读基线。
- 建议：周期性（如每周）把 `core/*.py` 镜像到受保护的备份目录，多一道离线冗余。

### 约束 5【可选】编辑器防覆盖
- 在编辑器（VSCode 等）中开启「文件被外部修改时提醒」「保存前备份」，
  降低编辑器自身误写风险。

## 三、commit 是否应升级为例行动作？—— 结论：是，且已是高优先级

- **应**。本次事故的可恢复性差，100% 源于「无 commit」。有 commit 就不会有「blob 丢失」。
- **建议做法**：
  1. 每个任务/实质性改动结束即 `git commit`（本地，不 push 也行）。
  2. 提交信息写清「做了什么 + 关联任务」，便于日后 `git bisect`/`git log` 定位。
  3. 保留 `hooks/pre-commit`（quality_gate + 收缩守卫），提交即自检。
  4. 需要回滚时用 `git reset --soft` / `git revert`，不强制 `--hard`。
- **代价**：极低（本地提交秒级、可逆、不污染远程）；收益：从「不可恢复」变「秒级找回」。
