# Web 操盘台 v2 原型 · 交易员高频使用场景覆盖评审

> 评审对象：`docs/prototype_web_dashboard_v2.html`（交互式原型，commit `113930b`）
> 评审视角：Al Brooks 价格行为（PA）摆荡交易者 + 人机协作（只推信号不下单）
> 评审方法：先**推演用户未来真实使用场景**（按频率分档），再逐场景比对原型覆盖度，找出"高频但原型没接"的缺口。
> 配套文档：需求规格 `Web操盘台v2_需求规格与设计方案.md`、UX 评审 `Web操盘台v2_原型UX评审.md`

## 一、角色与上下文设定（推演前提）

本系统用户 = **A 股 PA 摆荡交易员**，非程序员，前端出身。工作流是"**系统推信号 → 自己看形态判断是否建仓 → 自己下单**"，机器不替他做决定。

数据现实（已查实，非臆测）：
- 注册表官方 6 策略（`core/strategy_registry.py:57`）：`MTR_MASTER`（日线）、`STRATEGY_3K`（日线，负 EV）、`STRATEGY_STRUCTURAL_GAP`（缺口 H1，周线为主）、`STRATEGY_GAP_PINBAR`（缺口 PINBAR，周线）、`STRATEGY_GAP_H2`（缺口 H2，周线）、`STRATEGY_AWIL`（日线）。
- 周线**缺口家族 3 个**（STRUCTURAL_GAP / GAP_PINBAR / GAP_H2）是**唯一 EV 为正的周线策略**；日线普遍弱（3K 已证伪正 EV）。
- 数据：Baostock 离线 T+1，信号归档在 `signal_archive`；"截至某周仍存活"口径 = `signal_date<=W AND (resolved_date IS NULL OR resolved_date>W)`（`gui_dashboard.py` 既有逻辑）。
- 已有真实产物：`strategy_lab/weekly_ambush_plan.md`（周线埋伏计划，待挂单/观察池）、`tools/journal.py` 的 `hunter_journal`/`guardian_journal`（交易日志数据层）。
- 红线（须规避）：不显示字母评级、不实现市场状态自动识别、PA 因子禁成交量/指标/基本面。

## 四、关键覆盖缺口（按对交易员价值排序）

### 缺口 1 — 周线埋伏计划视图（S5，🔴 最高价值缺失）
`weekly_ambush_plan.md` 是周线交易员**每周的决策输入**（待挂单 + 观察池 + 触发条件），原型 7 页无一接它。交易员周末的核心问题"下周盯哪些、触发条件是什么"，原型答不了。
**建议**：新增"埋伏计划"区块（可并入看板或独立页），只读渲染该 md 的结构化内容（待挂单/观察池两栏 + 生成时间 + 扫描范围），数据源标 `strategy_lab/weekly_ambush_plan.md`。不进数据库，零风险。

### 缺口 2 — 多周期并呈（S2，🔴 PA 命门）
PA 实战是"周线定背景 → 日线找信号"。原型信号抽屉只有单根 K 线放大图，**没有周线背景框 + 日线信号同屏**。这恰是 UX 评审已提、原型未补的"多周期上下文工作流"。
**建议**：信号抽屉升级为上下双图（上=周线背景，下=日线/触发 K 线），或详情页双周期联动。

### 缺口 3 — 按周存活下拉不可用（S6，🔴 = P0）
原型周线下拉的 `onchange` 是空函数，而"截至该周仍存活"是项目已定夺的核心口径。这正是用户铁律"所有控件必须可交互"被破之处。
**建议**：P0 修复——下拉取到真实周列表，切换后用存活口径重算信号列表。

### 缺口 4 — 缺口存活状态列（S10，🔴 = P1）
缺口家族是唯一正 EV 周线策略，其"存活/已补"状态（low 是否破 gap_floor）是交易员每日必看。信号列表无此列。
**建议**：信号中心增加"缺口状态"列（存活/已补/失效），颜色+文字双标识。

### 缺口 5 — 交易日志/复盘（S11，🔴）
`hunter_journal`/`guardian_journal` 表已在 `tools/journal.py:54/73` 存在，但原型无任何入口。交易员建仓/离场/复盘无处记。
**建议**：二期新增"日志/复盘"页（只读现有表 + 简单录入），不碰 schema 主人规则（journal.py 本就是该表主人）。

### 缺口 6 — 全局股票检索（S13，🔴）
现有搜索只在信号列表内。交易员常要"这只票历史上所有信号/跨周期"一查到底。
**建议**：顶栏全局搜索框，输入代码/名称 → 聚合该票全部信号（日/周/各策略）。

### 缺口 7 — 入场/失效价标注线（S2，🟡 = P1，UX 评审已提）
抽屉大图没画入场价线、失效价线。PA 交易者看图第一眼要找这两条线。
**建议**：K 线 SVG/图表上叠加水平标注线（入场=蓝、失效=红）。

### 缺口 8 — 双轨过渡期状态可见（S12，🟡）
阶段 1-2 期间"Web 看 + Tk 干"，交易员在 Web 端看不到下载/扫描是否在跑、跑到哪。
**建议**：看板加一行"数据管道状态"（只读 Tk 台最近一次运行回执/日志摘要），或二期用 SSE 接管后自然消失。

## 六、结论与优先级

**原型覆盖了约 44% 的高频场景，但漏掉了 3 个交易员周/日核心动作的入口**：周线埋伏计划（S5）、按周存活（S6）、缺口存活状态（S10）。这三项不补，原型对"周线 PA 摆荡交易员"而言是"好看但接不住决策"的壳——与 UX 评审"皮贴了骨没翻译"的结论一致。

**转 React 前必须修（P0，与 UX 评审合并执行）：**
1. 周线下拉按存活口径真实可用（S6）
2. 策略命名对齐 `get_metadata()['display_name']`（UX P0）
3. 全局焦点环（UX P0）

**阶段 1 前必须补（P1）：**
4. 周线埋伏计划视图（S5，最高价值）
5. 信号列表"缺口存活"列（S10）
6. 抽屉 K 线叠加入场/失效价标注线（S2/S7）
7. 多周期并呈（周线背景 + 日线信号，S2）

**阶段 2 / 二期考虑（P2）：**
8. 交易日志页（S11，数据层已就绪）
9. 全局股票检索（S13）
10. 双轨过渡期管道状态（S12）
11. 关注标记呈现（S16）、同码聚合（S17）
