# Web 操盘台 v2 原型 · 交易员高频使用场景覆盖评审（v2，交易员视角修正版）

> 评审对象：`docs/prototype_web_dashboard_v2.html`（交互式原型，commit `113930b`）
> 评审视角：Al Brooks 价格行为（PA）摆荡交易者 + 人机协作（只推信号不下单）
> 评审方法：**先推演交易员真实决策流，再比对原型能否接住每个决策所需的信息与动作**。
> 配套文档：需求规格 `Web操盘台v2_需求规格与设计方案.md`、UX 评审 `Web操盘台v2_原型UX评审.md`
> **修订说明**：v1 版本把"系统页面点击流程"误写成"交易员操作"，视角错误。本版完全按交易员的心理动作与决策流重写。

## 一、角色与上下文设定（推演前提）

本系统用户 = **A 股 PA 摆荡交易员**，非程序员，前端出身。工作流是"**系统推信号 → 自己看形态判断是否建仓 → 自己下单**"，机器不替他做决定。

数据现实（已查实，非臆测）：
- 注册表官方 6 策略（`core/strategy_registry.py:57`）：`MTR_MASTER`（日线）、`STRATEGY_3K`（日线，负 EV）、`STRATEGY_STRUCTURAL_GAP`（缺口 H1，周线为主）、`STRATEGY_GAP_PINBAR`（缺口 PINBAR，周线）、`STRATEGY_GAP_H2`（缺口 H2，周线）、`STRATEGY_AWIL`（日线）。
- 周线**缺口家族 3 个**（STRUCTURAL_GAP / GAP_PINBAR / GAP_H2）是**唯一 EV 为正的周线策略**；日线普遍弱（3K 已证伪正 EV）。
- 数据：Baostock 离线 T+1，信号归档在 `signal_archive`；"截至某周仍存活"口径 = `signal_date<=W AND (resolved_date IS NULL OR resolved_date>W)`（`gui_dashboard.py` 既有逻辑）。
- 已有真实产物：`strategy_lab/weekly_ambush_plan.md`（周线埋伏计划，待挂单/观察池）、`tools/journal.py` 的 `hunter_journal`/`guardian_journal`（交易日志数据层）。
- 红线（须规避）：不显示字母评级、不实现市场状态自动识别、PA 因子禁成交量/指标/基本面。

## 二、交易员真实决策流（按频率分档）

> 原则：以下"交易员动作"写**决策/判断/心理活动**，不写"点哪个按钮"。

### A 档 · 每个交易日盘后（最高频，决策核心）

| 编号 | 交易员决策/动作 | 心理白描 | 原型当前支持 | 缺口 |
|:---|:---|:---|:---|:---|
| A1 | **信号初筛：从噪声里挑出值得看的票** | "今天出了多少信号？先把明显作假的（比如 3K 逆大势硬弹）pass 掉，留下 3-5 个细看的。" | 信号中心列表 + PA 证据列 + 策略/状态筛选 ✓ | 缺"快速 pass/关注"一键动作（S16） |
| A2 | **单信号形态验证：判断能不能做** | "这个信号位置对不对？周线背景支持吗？触发 K 线强不强？入场价、失效价、盈亏比在哪里？" | 抽屉打开 ✓，PA 证据列 ✓ | **缺周线背景同屏**（多周期并呈 ✗）、**缺入场/失效价标注线**、缺盈亏比可视化 |
| A3 | **候选决策：入观察池 or 放弃** | "这个我要明天盯吗？加自选，还是 pass？pass 的原因是什么？" | 自选分组 + 添加按钮 ✓ | 缺 pass 原因的快速备注（日志入口 ✗） |
| A4 | **持仓/观察标的跟踪：老的单子怎么样了** | "我前几天加自选的票，今天触发入场了吗？破失效价了吗？缺口补了吗？" | 自选日/周缩略图 ✓ | **缺缺口存活状态**、缺"自选池内今日新信号"高亮、缺失效价触发提醒 |
| A5 | **盘后复核与日志补录** | "今天我 pass 了哪些、为什么？建仓了哪些？记一笔，周末复盘用。" | **原型无日志界面** ✗ | 完全缺失 |

### B 档 · 每个周末（高价值，布局下周）

| 编号 | 交易员决策/动作 | 心理白描 | 原型当前支持 | 缺口 |
|:---|:---|:---|:---|:---|
| B1 | **研读周线埋伏计划：下周打猎名单** | "下周重点盯哪些？触发条件是什么？价格到了挂不挂单？" | **完全未接 weekly_ambush_plan.md** ✗ | 最高价值缺失 |
| B2 | **周线存活清单检查：哪些老信号还活着** | "前两周周线缺口信号，这周还存活吗？有没有适合回补买入的？" | 周线下拉存在但 **onchange 是空函数** ✗ | P0 |
| B3 | **策略健康度检查：最近谁在给我赚钱** | "哪个策略最近信号质量高/低？我是不是该把 3K 的权重放低？" | 策略卡 EV 排序 ✓ | 卡内 EV 是示意值，需接真实回测 |

### C 档 · 触发式/按需（中低频）

| 编号 | 交易员决策/动作 | 心理白描 | 原型当前支持 | 缺口 |
|:---|:---|:---|:---|:---|
| C1 | **听到某只股票，查它全部历史信号** | "朋友提到 600xxx，我系统里有没有它的日/周信号？历史表现如何？" | 仅信号列表内搜索 ✗ | 缺全局股票搜索 |
| C2 | **回测验证某个策略想法** | "3K 最近总是亏，回测一下它这一年的净值和胜率。" | 回测页示意 ✓ | 示意数据，未接真实回测 |
| C3 | **分享一个信号给别人看** | "这个周线缺口形态很好，截图发群里。" | HTML 可截图，但无标注辅助 | 缺一键标注/导出 |
| C4 | **调整个人偏好** | "把默认周期改成周线、切浅色主题。" | 设置页 ✓ | — |

### D 档 · 系统运维（必要但非交易）

| 编号 | 动作 | 说明 | 原型支持 |
|:---|:---|:---|:---|
| D1 | 确认今日数据已下载 | 运行扫描/看信号前的 precondition | 看板数据新鲜度 ✓ |
| D2 | 运行下载/扫描/终止 | 操作动作，当前由 Tk 台负责，二期搬 Web | 二期（双轨期状态不可见） |

## 四、关键覆盖缺口（按交易员决策价值排序）

### 缺口 1 — 单信号形态验证缺多周期并呈（A2，🔴 PA 命门）
PA 实战是"周线定背景 → 日线找信号"。原型信号抽屉只有单根触发 K 线放大图，**没有周线背景同屏**。交易员无法判断日线信号是不是在周线关键位置/趋势里出现的。这是所有形态判断的前提。
**建议**：信号抽屉或详情页至少做"上=周线背景，下=日线触发 K 线"双图联动；入场/失效价两条水平线在两张图上同时标出。

### 缺口 2 — 周线埋伏计划视图（B1，🔴 最高价值缺失）
`weekly_ambush_plan.md` 是周线交易员**每周的决策输入**（待挂单 + 观察池 + 触发条件）。原型 7 页无一接它。交易员周末核心问题"下周盯哪些、什么条件动手"，原型答不了。
**建议**：新增"埋伏计划"页或在看板置顶区块，只读渲染该 md 的结构化内容；数据源标 `strategy_lab/weekly_ambush_plan.md`，不进数据库，零风险。

### 缺口 3 — 交易日志/复盘入口（A5，🔴）
交易员每天都会 pass/建仓，需要快速记原因。`hunter_journal`/`guardian_journal` 表已在 `tools/journal.py:54/73` 存在，但原型无任何入口。
**建议**：二期新增"日志/复盘"页；阶段 1 可在信号抽屉先加一个"记一笔"按钮（录入 pass/建仓/离场 + 原因）。

### 缺口 4 — 按周存活下拉不可用（B2，🔴 = P0）
原型周线下拉 `onchange` 是空函数，而"截至该周仍存活"是项目已定夺的核心口径。违反"所有控件必须可交互"铁律。
**建议**：P0 修复——下拉切换后按存活口径重算信号列表。

### 缺口 5 — 缺口存活状态与失效触发提醒（A4，🔴）
缺口家族是唯一正 EV 周线策略，交易员每日必看"缺口补了没/破失效价没"。自选列表和信号列表均无此列，也无破价高亮。
**建议**：信号中心加"缺口状态"列（存活/已补/失效）；自选池加"今日触发事件"（新信号/破失效/到目标）。

### 缺口 6 — 入场/失效价标注线（A2，🟡）
抽屉大图没画入场价线、失效价线。PA 交易者看图第一眼要找这两条线。
**建议**：K 线图上叠加水平标注线（入场=蓝、失效=红）。

### 缺口 7 — 全局股票检索（C1，🟡）
交易员常因外部信息查某只票的完整历史信号。现有搜索只在信号列表内。
**建议**：顶栏全局搜索框，输入代码/名称 → 聚合该票全部信号（日/周/各策略）。

### 缺口 8 — 双轨过渡期操作状态（D2，🟡）
阶段 1-2 期间"Web 看 + Tk 干"，交易员在 Web 端不知道下载/扫描是否在跑。
**建议**：看板加一行"数据管道状态"（只读 Tk 台最近一次运行回执），或等二期 SSE 接管后自然消失。

## 五、v1 错在哪（反思）

v1 表格把"打开看板→点事件流""点信号行→看抽屉"这类**UI 点击路径**误当作"交易员实际操作"。这不是场景推演，这是原型 walkthrough。

真正的高频场景应该是**决策**——"过滤噪声""验证形态""决定入池或放弃""跟踪旧标的""记日志""读埋伏计划"。本版已按此修正。

## 六、结论与优先级

**原型对交易员核心决策流的覆盖很弱**：A/B 档 8 个高频决策动作里，只有 2 个完全覆盖（信号初筛、策略健康度），4 个完全缺失（形态验证的多周期并呈、埋伏计划、日志、周线存活），2 个部分覆盖（候选入池/放弃、老标的跟踪）。

**转 React 前必须修（P0）：**
1. 周线下拉按存活口径真实可用（B2）
2. 策略命名对齐 `get_metadata()`（UX P0）
3. 全局焦点环（UX P0）

**阶段 1 前必须补（P1）：**
4. 信号详情多周期并呈 + 入场/失效价标注线（A2）
5. 周线埋伏计划视图（B1）
6. 缺口存活状态列 + 失效触发提醒（A4）
7. 信号抽屉"记一笔"日志快速入口（A5 的 MVP）

**阶段 2 / 二期考虑（P2）：**
8. 完整日志/复盘页（A5）
9. 全局股票检索（C1）
10. 双轨过渡期管道状态（D2）
11. pass/关注快速动作与备注（A1/A3）
