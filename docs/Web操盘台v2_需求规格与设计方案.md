> **本文档定位**：项目 GUI 从 Tkinter 桌面端升级为浏览器端前的**评审稿**。所有结论带出处（行号/截图/实测），所有分歧点带备选方案，所有红线动议带修订理由。读完本文档并确认后，方进入开发阶段。

## §1 概述：为什么做、做给谁、做到什么程度

### 1.1 项目现状（一句话）
一个用 Tkinter（Python 自带桌面界面库，Tk 版本 8.6）写的离线量化扫描操盘台，数据底子是 584MB Baostock SQLite 库，6 个 PA（Price Action，纯价格行为）策略日/周双周期扫描，只推信号不下单。

### 1.2 升级动机（用户原话+翻译）
用户原话：**"整体和细节均未达到对外分享交流的程度"**。

大白话翻译：现在的界面像十年前的工具，自己用凑合，发给朋友看丢脸。借 TSP 的外壳是要**拿到能截图/录屏发出去不丢人的视觉品质**。

### 1.3 已拍板的决策（10 条，评审时不可漂移）

| # | 决策 | 出处 |
|:---|:---|:---|
| 1 | **换 Web 技术栈**，整体替换 Tk 操盘台 | 用户拍板（烤问第一轮） |
| 2 | 品质标准 = "对外分享交流的程度"，**截图分享级**（localhost 自用，不对外开端口） | 用户拍板（烤问第二轮） |
| 3 | 前端框架由我定（推荐 React，原因：和 TSP 同栈，可解剖它的源码） | 用户拍板 |
| 4 | K 线图用**交互式专业库**（Lightweight Charts / KLineCharts） | 用户拍板（烤问第二轮） |
| 5 | 首期**只做"看+筛"**：看板 / 信号中心 / 自选 / 策略页，**全部只读** | 用户拍板（烤问第三轮） |
| 6 | 下载行情 / 扫描 / 终止等操作功能**二期搬**，进度用 SSE 流式 | 用户拍板 |
| 7 | **回测可视化放二期** | 用户拍板 |
| 8 | **Tk 操盘台最终退役**，Web 按"唯一长期界面"设计 | 用户拍板 |
| 9 | **数据引擎换评估作为独立事项**：先出对比报告再拍板 | 用户拍板 |
| 10 | **不借清单**：实时监控/语音（无实时数据）、连板梯队/概念轮动/异动（打板生态）、市场环境 Regime（撞红线）、因子挖掘（撞 PA 铁律） | 用户拍板 |

### 1.4 红线（动议前须知）
本项目有 8 条红线（参见 `docs/项目自述_面向Agent.md §5`），其中：
- **红线 C7（不实现市场状态自动识别）** —— 直接砍掉 TSP 的"市场环境 Regime"页
- **红线 PA-1（因子只能是价格行为本身）** —— 直接砍掉 TSP 的"因子挖掘 Mining"页
- **红线 D5（K 线图复用 `notifier.generate_chart_bytes`）** —— **本方案拟修订**，理由见 §6
- **红线 DATA-1（不动 `data/*.db*` 结构）** —— 本方案严守：只读 + 隔一层数据接口

## §2 技术栈选型

### 2.1 选型总表

| 层 | 选型 | 理由 |
|:---|:---|:---|
| 后端 Web 框架 | **FastAPI** + Pydantic v2 | 与 TSP 同栈；自动 OpenAPI（接口说明书）/ 异步 / 类型校验；与现有 .venv Python 3.13 兼容 |
| 后端 ASGI（Web 服务器接口） | Uvicorn | FastAPI 标准搭档 |
| SSE 推流 | **sse-starlette** | 操作类功能（二期）的进度推送，TSP 同款 |
| 数据库访问 | **仅只读** + 隔 `core/database.py` | 严守 schema 冻结；不绕过 |
| 前端框架 | **React 18** + TypeScript | 与 TSP 同栈，可解剖；类型安全 |
| 构建 | **Vite** | 与 TSP 同栈，启动快 |
| 样式 | **Tailwind CSS 3** + CSS 变量主题 | 直接套用 TSP 的 `index.css` 设计语言 |
| 数据请求 | **Tanstack Query (React Query)** | 缓存/重取/loading 状态管理，TSP 同款 |
| 表格 | **TanStack Table v8**（headless 无样式表格库） + Tailwind 样式 | 支持列排序/筛选/虚拟滚动（成百上千行不卡） |
| K 线图 | **lightweight-charts**（TradingView 开源免费版，业内标准） | TSP 同款；缩放/十字光标/多周期切换；体积比 ECharts 小 |
| 拖拽分组 | **dnd-kit** | 自选页多分组拖拽 |
| 图表（柱状/雷达/六边形情绪） | **ECharts 5** | TSP 同款；适配深色主题 |
| 图标 | **lucide-react** | 现代、简洁、tree-shakable（按需打包，未用图标不进产物） |
| 字体 | 系统等宽 + Inter | 数字一律等宽（tabular-nums + mono） |
| 部署 | Vite dev server 开发期；二期再考虑单容器 | D 盘空间紧张，Docker 镜像暂缓 |

### 2.2 与现有 Python 环境隔离
- 复用现有 `.venv`（Python 3.13），不新建环境
- 新增 pip 包：`fastapi`、`uvicorn[standard]`、`sse-starlette`、`pydantic`
- 前端独立：`frontend/` 目录，Vite 项目；npm 依赖在前端子目录
- 启动脚本：`launch_web_dashboard.bat` / `launch_web_dashboard.vbs`（沿用用户桌面双击习惯）

### 2.3 关键决策点（待评审）

| 待拍板项 | 我的建议 | 备选 |
|:---|:---|:---|
| 前端包管理 | **pnpm**（TSP 同款，D 盘友好，体积小） | npm（如果用户更熟） |
| Node 版本 | **20 LTS** | — |
| 是否要 TS | **要**（质量门禁会更严格，TypeScript 类型错误红线化） | JS（更快但维护期更痛） |

## §3 设计语言

> **来源**：直接套用 TSP 的 `frontend/src/index.css` 设计变量（已读源码），按中国 A 股 红涨绿跌惯例适配。

### 3.1 深色主题（默认）

| 变量 | HSL 值 | 颜色 | 用途 |
|:---|:---|:---|:---|
| `--base` | 240 5% 5% | `#0A0A0B` | 全局背景（接近纯黑的深灰） |
| `--surface` | 240 7% 10% | `#18181B` | 卡片底色（略亮，对比清晰） |
| `--elevated` | 240 9% 14% | `#212126` | 悬浮卡片 / 浮层 |
| `--border` | 240 5% 22% | `#353539` | 1px 细分隔线（不用 shadow） |
| `--fg-primary` | 0 0% 98% | `#FAFAFA` | 主文字 |
| `--fg-secondary` | 240 5% 78% | `#C4C4CB` | 次文字 / 导航未激活 |
| `--fg-muted` | 240 5% 58% | `#8E8E96` | 辅助提示 |
| `--accent` | 217 91% 60% | `#3B82F6` | 电光蓝（主交互色） |
| `--bull` | 4 87% 60% | **`#F04438` 红涨** | A 股 惯例：涨 = 红 |
| `--bear` | 152 67% 45% | **`#12B76A` 绿跌** | A 股 惯例：跌 = 绿 |
| `--warning` | 32 95% 50% | `#F79009` | 橙黄（提示/警告） |
| `--danger` | 4 87% 60% | `#F04438` | 红色（危险/止损） |

> **关键发现**：TSP 的 CSS 变量注释里已写 `--bull: 4 87% 60% #F04438 红涨` —— 它就是按中国 A 股惯例设计的（与多数西方工具相反）。我们直接沿用，颜色不需要改。

### 3.2 设计原则（从 TSP 提炼）

1. **暗色为默认**（`html.dark`）；亮色用 `:root` 反转；用户可在设置切换
2. **HSL 而非 hex** —— 兼容 Tailwind alpha-value 语法（`bg-base/50` 这种半透明）
3. **价格 / 数字一律等宽** —— `font-variant-numeric: tabular-nums` + `font-mono`
4. **1px 细分隔线 + 不用 shadow** —— 暗色环境下边框比阴影更清晰
5. **细滚动条** —— 8px 宽、圆角、悬停变 accent 色
6. **不强制 antialiasing**（暗色模式）—— 让字形饱满不发虚
7. **grid 12-16 列响应式** —— 桌面端信息密度高，移动端不优化（先桌面体验极致）

## §4 信息架构与导航

### 4.1 简化导航（从 TSP 24 个页面砍到 7 个）

```
┌─ 左侧栏 ──────────────────┐
│ 🏠 看板       Dashboard   │ ← 默认首页
│ 📡 信号中心   Signals     │ ← 日/周切换 + 待建仓
│ ⭐ 自选       Watchlist   │ ← 多分组升级
│ 🎯 策略       Strategy    │ ← 策略卡片化
│ 📈 回测       Backtest    │ ← 二期
│ 💾 数据画像   Data        │ ← 二期（独立评估后）
│ ⚙ 设置       Settings    │
└──────────────────────────┘
底部状态栏：扫描时间 / 数据覆盖到哪天 / 当前周期（daily/weekly）
```

### 4.2 导航顺序的设计原则
- 使用频率从高到低：看板（一眼看全）→ 信号（实际操作）→ 自选（盯盘）→ 策略（研究）→ 设置
- 二期页面（回测/数据画像）放在设置前面，预留位置但不暴露空壳
- 删除所有与本项目定位不符的页面（连板梯队/概念轮动/异动/监控中心/复盘/财务分析/挖掘/Regime/指数）

## §6 K 线图方案（要动红线 D5，必须拍板）

### 6.1 红线 D5 现状
原文：> "K 线图：复用 `notifier.generate_chart_bytes`，禁另写绘图；横轴用整数 0..N-1，禁传 Timestamp。"

**适用范围回顾**：这是为 Tk 缩略图和 Discord 推送定的（后端生成 PNG 二进制）。

### 6.2 拟修订（D5 v2）
> **D5 v2**：K 线图渲染按场景分两类——
> - **后端/桌面/Discord 推送**：继续复用 `notifier.generate_chart_bytes`（已含 30 根 K 线 + 入场/止损线 + 因子标注），绘图代码一行不改。
> - **Web 端详情视图**：统一用 **`lightweight-charts`**（TradingView 开源标准库，业内 K 线库事实标准），前后端通过标准 OHLC JSON 协议对接；横轴时间用 ISO 8601 字符串（库自动转换），禁传 Timestamp 整数。

### 6.3 lightweight-charts 选型理由
- **TSP 同款**（截图证据：screener.png 主表每行右侧 K 线缩略图、`backtest.png` 主区——但回测页似乎是 ECharts，待核实）
- **TradingView 开源**（Apache-2.0 协议，免费商用）
- **功能全**：缩放、十字光标、指标叠加（MA/成交量/止损线）、多周期切换、缩略图模式（`mode: 'compact'`）
- **性能**：Canvas 渲染，万级数据点不卡
- **体积**：~250KB（vs ECharts ~900KB），适合每行嵌入缩略图

## §7 数据接口设计（隔一层）

### 7.1 分层

```
┌──────────────────────────────────────────────────────────┐
│ Frontend (React, 只读)                                   │
│   └─ TanStack Query → /api/v1/...                        │
├──────────────────────────────────────────────────────────┤
│ Backend (FastAPI, 只读 + 只调既有 core 接口)              │
│   ├─ /api/v1/dashboard/summary                           │
│   ├─ /api/v1/signals?timeframe=daily&week=...           │
│   ├─ /api/v1/watchlist/groups                           │
│   ├─ /api/v1/strategies                                 │
│   ├─ /api/v1/chart/{ts_code}                            │
│   └─ (二期) /api/v1/scan/daily (SSE 推流)                │
├──────────────────────────────────────────────────────────┤
│ Existing core (不修改，只读调用)                         │
│   ├─ core/database.py (schema 主人，DDL 唯一来源)        │
│   ├─ core/data_provider.py                              │
│   ├─ core/strategy_registry.py                          │
│   └─ core/scan_engine.py (二期写库，一期不调用)          │
└──────────────────────────────────────────────────────────┘
```

### 7.2 硬约束
- Web 后端**严禁**：
  - 写库
  - 改 schema
  - 直接 SQL（必须经 `core/database.py` 提供的查询函数）
  - 触发 `data_provider.update_*_batch`（一期）
- Web 后端**允许**：
  - 读 `signal_archive` / `daily_bars` / `weekly_bars`
  - 调 `core/strategy_registry.get_metadata()` 拿策略信息

### 7.3 错误处理与日志
- 后端日志：`logs/web_backend.log`（与现有 `logs/` 同目录，不混文件）
- 前端错误：TanStack Query 自动 retry + 友好 toast
- API 错误统一格式：`{"error": {"code": "...", "message": "大白话"}}`
