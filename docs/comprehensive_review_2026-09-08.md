### 需要修复的问题

#### 🔴 P0 — 开工前必改

**P0-1: 策略名 `AIL` 与注册表不符**

```javascript
// prototype_web_dashboard_v2_rebuilt.html:291
{key:'STRATEGY_AWIL', name:'AIL', tf:['daily']},
```

注册表官方 `display_name` 是 `AWIL`（Always-In-Long），不是 `AIL`。这属于"无来源字段"——正是自述文档§〇第2条"核实铁律"禁止的行为。

**修复**: 改为 `name:'AWIL趋势'`（对齐 `get_metadata()['display_name']`）

---

**P0-2: `GAP H1` 不是注册表display_name**

```javascript
// :288
{key:'STRATEGY_STRUCTURAL_GAP', name:'GAP H1', tf:['daily','weekly']},
```

注册表中该策略的 `display_name` 应确认是否真的叫"GAP H1"。如果是"结构缺口"之类，这里就是硬编码的错误花名。**必须从 `get_metadata()` 取真实值**。

---

**P0-3: 样本数据中出现PA领域不存在的概念**

```javascript
// :304
{code:'601318', ..., ev:-0.18, ..., evi:'日线 MTR 双底，但大环境偏弱'},
//                                         ^^^^^^^^^^^^^^^^
```

"大环境偏弱"——这触碰了自述文档§1中明确禁止的"市场状态自动识别"红线。虽然这只是原型样本数据中的文案，但如果在正式版中由AI审计模块生成类似文案，就会违反PA纯粹性。

**建议**: 修改为纯PA语言，如"日线MTR双底，但EMA20仍下倾"。

---

**P0-4: 样本中 `量能不足` 是PA违禁表述**

```javascript
// :304
{code:'600276', ..., evi:'日线 MTR，量能不足'},
//                              ^^^^^^^^^^^^
```

"量能"即成交量，是PA明确排斥的因子。原型样本数据中出现此表述，如果被前端开发者当作模板照搬，会在正式版中引入违禁展示。

**修复**: 改为纯PA描述，如"日线MTR，信号K实体偏小"。

---

#### 🟡 P1 — 正式版前定稿

**P1-1: 信号表缺少"止盈价"列**

信号中心表头有"入场价"和"失效价"(止损)，但没有"止盈价"(TP)。自述文档§5.2明确 `get_metadata()` 定义了 `tp_columns / tp_multiplier`，这是交易计划的核心三要素(Entry/SL/TP)，缺一不可。

---

**P1-2: 复盘回测页的净值/回撤/胜率图用硬编码数据**

```javascript
// :511
const data = btMetric==='equity'?cum([1,1.02,0.99,1.05,...]):...
```

原型阶段可接受，但正式版必须对接 `trade_reviews` 表的真实数据。自述文档§8.4已标明"字母评级已证伪，EV为唯一评估标准"——回测页应以EV为核心指标展示。

---

**P1-3: 抽屉中的K线图EMA/指标按钮**

```javascript
// :423
<span style="margin-left:auto;color:var(--fg-muted)">指标 ▾</span>
```

"指标"按钮暗示可添加技术指标叠加显示。PA体系排斥技术指标，这个按钮在正式版中应该只允许叠加EMA（作为PA的制度参考），不应出现MACD/RSI/BOLL等选项。

---

**P1-4: 数据画像页的"缺口/异常"卡片**

```javascript
// :550
<div class="v sm" style="color:var(--warn)">${isD?3:5}</div>
```

"缺口/异常"这个命名在PA系统中容易歧义——"缺口"是核心策略概念（Gap），不应和"数据异常"混用。建议改为"数据缺失/异常"。
